# Our Commitment

RelayDispatch is committed to fostering an open, welcoming, inclusive, and harassment-free environment for everyone.

We welcome contributors of all backgrounds, identities, experience levels, and perspectives.

Participation in the RelayDispatch community should always be based on mutual respect, professionalism, curiosity, and constructive collaboration.

We pledge to make participation in our community a positive experience regardless of:

- Age
- Body size
- Disability (visible or invisible)
- Ethnicity
- Sex characteristics
- Gender identity or expression
- Sexual orientation
- Race
- Nationality
- Religion
- Caste
- Color
- Language
- Education
- Socio-economic status
- Geographic location
- Technical experience

Everyone deserves to feel safe while participating in the project.

---

# Community Values

RelayDispatch is built around several core values.

## 🤝 Respect

Treat everyone with dignity.

Disagreement is expected.

Disrespect is not.

---

## 💡 Collaboration

Assume good intentions.

Help others learn.

Share knowledge openly.

Support contributors instead of competing with them.

---

## 🌍 Inclusion

We actively encourage participation from developers with diverse experiences, cultures, backgrounds, and skill levels.

Questions are welcome.

Learning is encouraged.

Gatekeeping is discouraged.

---

## 📖 Transparency

Technical discussions should happen publicly whenever practical.

Architectural decisions should be documented.

Constructive feedback should remain respectful and evidence-based.

---

## 🔒 Responsibility

Security, privacy, and responsible disclosure are shared responsibilities.

Community members are expected to protect users, contributors, and the project itself.

---

# Expected Behavior

Examples of positive behavior include:

- Being respectful during technical discussions
- Helping newcomers understand the project
- Accepting constructive criticism professionally
- Providing thoughtful code reviews
- Giving credit to others
- Respecting different viewpoints
- Being patient when answering questions
- Improving documentation
- Reporting bugs responsibly
- Sharing knowledge openly
- Focusing discussions on technical merit

---

# Unacceptable Behavior

The following behaviors are not tolerated.

## Harassment

Including but not limited to:

- intimidation
- stalking
- threats
- deliberate exclusion
- repeated unwanted contact

---

## Personal Attacks

Including:

- insults
- ridicule
- name calling
- degrading comments
- hostile interactions

Critique ideas—not people.

---

## Hate Speech

Any content targeting protected groups through:

- discrimination
- demeaning language
- hateful imagery
- incitement

is prohibited.

---

## Sexual Content

Including:

- unwanted sexual attention
- inappropriate advances
- explicit comments
- sexualized imagery in project spaces

---

## Privacy Violations

Do not publish another person's:

- address
- phone number
- email
- workplace
- private conversations
- personal photographs
- credentials
- security information

without explicit permission.

---

## Malicious Activity

The following actions may result in immediate removal:

- intentionally introducing malware
- credential theft
- supply-chain attacks
- publishing exploits before coordinated disclosure
- denial-of-service attacks
- spam
- impersonation
- social engineering against contributors

---

# Open Source Etiquette

Please remember:

- Review code respectfully.
- Explain decisions.
- Avoid sarcasm in technical reviews.
- Welcome first-time contributors.
- Keep discussions focused on improving the project.

Disagreement is normal.

Hostility is not.

---

# Scope

This Code of Conduct applies to all official RelayDispatch spaces, including:

- GitHub repositories
- Pull Requests
- Issues
- Discussions
- Documentation
- Project websites
- Community chat platforms
- Social media accounts
- Conference presentations
- Workshops
- Community events
- Any space where someone is representing RelayDispatch

It also applies to private interactions when they substantially affect the health or safety of the community.

---

# Maintainer Responsibilities

Project maintainers are responsible for:

- enforcing this Code of Conduct fairly
- investigating reports promptly
- protecting reporter confidentiality whenever possible
- documenting enforcement actions
- avoiding conflicts of interest during investigations

Maintainers may remove, edit, or reject contributions that violate these standards.

---

# Reporting Violations

If you experience or witness behavior that violates this Code of Conduct, please report it privately.

Include when possible:

- description of the incident
- relevant links
- screenshots (if applicable)
- dates and times
- participants involved

Reports should be sent to:

**uzair.shaikh.sec@outlook.com**

Please do **not** create a public GitHub issue for Code of Conduct violations.

---

# Enforcement Process

Each report will be:

1. acknowledged
2. reviewed
3. investigated
4. discussed by maintainers
5. resolved as fairly and consistently as possible

Whenever appropriate, maintainers will communicate the outcome to the reporting party.

---

# Enforcement Guidelines

Enforcement decisions consider:

- severity
- intent
- frequency
- previous incidents
- impact on the community
- willingness to correct behavior

Possible actions include:

## Level 1 — Correction

Private communication explaining:

- the concern
- why it violates the Code
- expected future behavior

---

## Level 2 — Official Warning

Formal written warning.

Additional violations may lead to temporary suspension.

---

## Level 3 — Temporary Suspension

Temporary removal from:

- GitHub discussions
- Issues
- Pull Requests
- Community spaces

Duration depends on severity.

---

## Level 4 — Permanent Removal

For repeated or severe misconduct, maintainers may permanently revoke participation privileges across official RelayDispatch communities.

---

# Appeals

Individuals subject to enforcement may request reconsideration by contacting the maintainers.

Appeals should include:

- additional context
- clarification
- evidence supporting reconsideration

Appeals will be reviewed by maintainers not directly involved in the original decision whenever practical.

---

# Responsible Security Research

Security researchers are welcome.

Please follow the project's responsible disclosure policy described in **SECURITY.md**.

Do **not** publicly disclose security vulnerabilities before maintainers have had a reasonable opportunity to investigate and release a fix.
